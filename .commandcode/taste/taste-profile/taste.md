# Taste Profile
- Works on React JSX web-store projects and expects work to stay inside the existing architecture: reuse existing components, hooks, API services, routing, and state management; preserve existing folder structure, naming conventions, imports/exports, and routing patterns. Confidence: 0.8
- Strongly prefers incremental, scoped changes over rewrites: audit the project first, report a short plan of files to change, and avoid large refactors or moving files without clear need. Confidence: 0.8
- Expects separation of concerns in components — split by function/responsibility and avoid one oversized component file. Confidence: 0.75
- Wants results reported transparently based on what was actually run, including testing limitations when a test could not be performed. Confidence: 0.8
- Requires all product/data to come from the backend API; forbids dummy, mock, or hardcoded data in the frontend (including to fill catalogs or stand in for API responses). When data is unavailable, use empty/loading/error states instead. Confidence: 0.85
- Forbids changing the frontend↔backend communication contract: no altering endpoints, HTTP methods, headers, params, payloads, response formats, auth mechanisms, or existing API services; UI should follow the existing API, not the reverse. Confidence: 0.85
- Preserves build/deployment configuration: do not merge frontend and backend build configs, do not change build/start scripts, bundlers, server config, output dirs, or deployment mechanism without approval; report build issues before changing anything unilaterally. Confidence: 0.8
- Forbids touching SQL/database: no edits to `query.sql`, SQL queries, schema, tables, migrations, or DB structure. Confidence: 0.85
- Forbids modifying, replacing, deleting, or exposing passwords, API secrets, access/refresh tokens, or request tokens; no credentials in frontend code, logs, docs, or public files; do not change `.env`, env var names, or auth config without explicit instruction; no moving backend secrets to frontend. Confidence: 0.85
- Forbids creating accounts/credentials or sensitive files for any reason (including testing): no new login/admin/user/test accounts, no hardcoded credentials or new auth systems, do not alter login/registration/session mechanisms. Authentication/account management is out of scope for UI tasks. Confidence: 0.8
- When a test requires auth or credentials that aren't available, expects the agent to skip it and report the limitation rather than working around it. Confidence: 0.75
- Expects responsive layouts validated across desktop, tablet, and mobile viewports, with careful attention to avoiding unintended horizontal overflow and preserving the existing mobile experience and visual identity. Confidence: 0.75
- Prefers communication in Indonesian (task briefs and instructions are written in Indonesian). Confidence: 0.7
