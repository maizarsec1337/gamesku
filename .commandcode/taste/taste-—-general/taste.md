# Taste — General
- Communicates in Indonesian (Bahasa Indonesia) and expects replies in Indonesian. Confidence: 0.9
- Do not claim success (e.g. "app is safe", "build passed", "all files intact") unless it was actually verified; state limitations honestly when something could not be checked. Confidence: 0.8
- Absolutely no demo/mock/dummy/placeholder data or demo mechanisms anywhere in the application: no mock APIs, demo/mode-demo logins, dummy accounts, seed/fixture/sample data, or generator scripts — the app must use real implementations and real data flows. Confidence: 0.9
- When real data is unavailable (empty DB, failed API, dropped connection), show proper empty states and honest error messages instead of silently falling back to sample/example data. Confidence: 0.85
- Prefers actual implementation, testing, and fixing over analysis, plans, or reports — do not stop after producing a report or a set of suggestions; implement directly. Confidence: 0.85
- Do not pause to ask approval for every routine, safe change; make reasonable technical decisions autonomously and keep working. Confidence: 0.75
- Preserve the existing tech stack, architecture, and dependencies; don't replace or rewrite them wholesale without a strong technical reason. Confidence: 0.8
- Don't treat a UI success notification (or a UI that merely appears to work) as proof a process actually succeeded — only real, verified outcomes count; no fake or optimistic "saved/success" feedback. Confidence: 0.8
- Maintain a single source of implementation: find the component/stylesheet the app actually uses (e.g. the one wired up in the router) and edit it in place instead of creating parallel or duplicate components, routes, or CSS. Confidence: 0.8
- Reuse existing components, assets, and stylesheets rather than introducing new ones, and don't add new dependencies unless genuinely necessary. Confidence: 0.75
- Make changes without regressing other pages/features (register, password reset, and unrelated pages must keep working). Confidence: 0.7
- Expect the agent to persist end-to-end until the issue is actually resolved — "run this command yourself" instructions are treated as insufficient; set up the environment, start the services, and test. Confidence: 0.8
- Expect a final report that explicitly separates what was verified/working from what could not be tested, including the concrete remaining blocker and the exact next step needed. Confidence: 0.8
- Keep the final report concise and scannable — use short sections and tables over long prose. Confidence: 0.7
- Never invent unspecified business/commission/pricing/registration rules; when business information is unavailable, implement only safe defaults and report the owner-decision points that need resolving, and never surface financial metrics (commission, balances, transactions, statistics) whose data sources have not been defined. Confidence: 0.9
